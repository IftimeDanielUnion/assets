## So erstellst du einen Tag selbst

Am einfachsten direkt in GitLab:

1. `catalog`-Repository öffnen.
2. Code → Tags → New tag auswählen.
3. Neue Versionsnummer eingeben, beispielsweise `v0.13.2`.
4. Unter Create from den gemergten Commit aus `main` auswählen.
5. Create tag klicken.

Das geht auch über dein WSL-Terminal:

```
cd ~/repos/catalog

git switch main
git pull --ff-only origin main

git tag -a v0.13.2 -m "Release v0.13.2"
git push origin v0.13.2
```

Der neue Tag zeigt dann auf den aktuellen lokalen `main`-Commit.&#x20;

Wichtig für euren Workflow:

- Immer erst den Catalog-MR mergen, dann taggen.
- Versionsnummer mit den bisherigen Tags abstimmen.
- Den Tag auf den richtigen Merge-Commit setzen.
- Anschließend im `live`-Repo `tg_catalog_version` auf die neue Version aktualisieren.
- Vor dem Merge in `live` den Terraform-Plan prüfen.

Tags können geschützt sein oder eigene Pipelines auslösen. Deshalb ist die kurze Abstimmung mit Timo sinnvoll.&#x20;
